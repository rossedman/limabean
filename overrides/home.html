Why limabean

A fresh Linux box whenever you want one.
Nothing to lose when you throw it away.

{% include ".icons/material/lightning-bolt.svg" %}

One command per VM

limabean new dev gives you an Ubuntu 26.04 VM with your git identity, ready in about a minute.

{% include ".icons/material/package-variant-closed.svg" %}

Batteries included

Docker Engine, Go, Python, Kubernetes tooling, Terraform and 30+ CLI tools, every version pinned with mise.

{% include ".icons/material/shield-lock-outline.svg" %}

Keys stay on your Mac

Pushes go through your forwarded ssh-agent. A scoped GitHub token lives in your Keychain, and git and AWS config are mounted read-only.

{% include ".icons/material/key-chain-variant.svg" %}

Secrets without files

API keys come from your Keychain, 1Password, environment variables or commands. You pick which ones a VM gets when you create it.

{% include ".icons/material/robot-happy-outline.svg" %}

Built for Claude

Each running VM shows up in Claude Desktop as an SSH connection. Claude works with the VM's tools and can't touch files on your Mac.

{% include ".icons/material/delete-restore.svg" %}

Safe to throw away

~/code lives on its own disk, so rebuild keeps your repositories, and rm refuses to run while you have unpushed work.

Quick start

Zero to a shell
in four commands.

limabean is a single binary with its VM templates built in. All it needs is macOS and Lima 2.0 or newer. Prebuilt binaries for Apple Silicon and Intel are on the releases page.

{% include ".icons/material/book-open-page-variant-outline.svg" %} Full getting-started guide

  1. Install Lima and limabean

    $ brew install lima
$ {{ install }}

  2. Set up once

    Saves your settings, fixes ~/.ssh/config and checks everything with doctor.

    $ limabean init

  3. Optional: give VMs GitHub access

    $ gh auth token --hostname github.com | limabean github login --with-token

  4. Create a VM and jump in

    $ limabean new dev
$ limabean ssh dev   # or: ssh lima-dev

How it works

Layered Lima templates.
No magic.

Every VM is built from ordinary Lima YAML and shell scripts, composed in layers. limactl always works, and you can add your own environments without rebuilding limabean.

layer-os

Ubuntu 26.04 LTS on Apple's Virtualization framework, VM size, agent forwarding, zsh as the login shell.

layer-base

What every VM gets: Docker Engine, mise-pinned tools, shell setup and the read-only git config mount.

environment

scratch out of the box, or your own in ~/.config/limabean/templates/.

Commands

A small CLI that
stays out of the way.

Leave out a VM name and you pick one from a list. Every command has --help with examples.

VMs

new
Create a VM, choosing its secrets
ls
List VMs
ssh
Open a shell, starting the VM if needed
get
Clone a repository into the VM with ghq
start / stop
Start or stop a VM
rebuild
Recreate from the current templates, keeping ~/code
rm
Delete a VM

Secrets

secrets ls
List secrets and where values come from
secrets set
Keychain, 1Password, env var or command
secrets rm
Remove a secret
secrets edit
Edit a secrets file in your editor
secrets sync
Install secrets in running VMs

Access & setup

init
Git config, code directory, SSH, GitHub
doctor
Check everything VMs depend on
github login
Save a scoped token for gh and the API
github status
Account, expiry and which VMs have it
claude sync
Register running VMs in Claude Desktop
